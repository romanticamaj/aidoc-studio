# P4 — Web Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Read `docs/superpowers/plans/2026-09-24-index.md` §8 (API contracts + event kinds) first. P3 must be complete and `aidoc serve` running for manual checks.

**Goal:** A SaaS-grade single-page app (Vite + React + TypeScript + Tailwind + shadcn/ui) with six pages — Convert, Jobs, Library, Document, Chunks, Settings — driven by the P3 API and SSE, built into `web/dist` and served by `aidoc serve`.

**Architecture:** TanStack Query holds server state; a single `EventStream` provider merges SSE events into the query cache via a pure `applyEvent` reducer; uploads run through a `hash-wasm` Web Worker and a resumable `uploadFile` routine; the Document page synchronises pdf.js pages with Markdown anchors produced by a custom remark plugin that turns `<!-- page: N -->` into `data-page` elements.

**Tech Stack:** Node 24, pnpm 10, Vite, React 19, TypeScript, Tailwind CSS, shadcn/ui, react-router, @tanstack/react-query, react-markdown + remark-gfm + remark-math + rehype-katex, pdfjs-dist, hash-wasm, Vitest + @testing-library/react + jsdom, Playwright.

**Spec:** §6 (all), §8.7 (client side), §9 (Settings), §10 (frontend tests), §12 P4, §13.4 (「重轉低品質」button).

## Global Constraints

Index §0 plus:
- All API calls go through `web/src/api/client.ts`; components never call `fetch` directly.
- Every API type in `web/src/api/types.ts` mirrors index §8 exactly (field names are the API's snake_case; no renaming layer).
- Token: read from `localStorage["aidoc_token"]`; sent as `Authorization: Bearer` on fetch and as `?token=` on `EventSource`.
- Dark mode: Tailwind `class` strategy; `<html class="dark">` toggled by the header switch; persisted in `localStorage["aidoc_theme"]`; default follows `prefers-color-scheme`.
- Traditional Chinese UI copy (labels below are given in 繁體中文 where the spec names them); code identifiers in English.
- No animation polish (spec §11).
- Vitest runs with `pnpm --dir web test`; Playwright with `pnpm --dir web e2e` (requires the server on `127.0.0.1:8765` with `AIDOC_FAKE_ENGINES=1`).

## Review Focus

1. A job with 0 tasks or a task with `pages: null` (docx) must render the progress bar without `NaN` — test in Task 6.
2. Reloading the page mid-upload must resume the same `upload_id` (sessionStorage keyed by name+size+lastModified) instead of starting over — test in Task 4.
3. A document whose Markdown has no `<!-- page: N -->` markers must still render and simply disable scroll sync — test in Task 8.
4. SSE `resync` must trigger a refetch of every jobs query and clear the stale log buffer flag — test in Task 3.
5. Library filter state must survive navigation to a document and back (URL search params, not component state) — test in Task 7.

### Task 4: Streaming sha256 worker and resumable upload

**Files:**
- Create: `src/upload/hashWorker.ts`, `src/upload/hashFile.ts`, `src/upload/uploadFile.ts`, `src/upload/useUploads.ts`, `src/upload/__tests__/uploadFile.test.ts`

**Interfaces:**
- `hashWorker.ts` (Worker): receives `{file: File}`; uses `hash-wasm` `createSHA256()`, reads the file in 8 MB slices via `file.slice(...).arrayBuffer()`, `update()` each, posts `{type: "progress", done, total}` and finally `{type: "done", sha256}`.
- `hashFile(file, onProgress?) → Promise<string>` wraps the worker (`new Worker(new URL("./hashWorker.ts", import.meta.url), {type: "module"})`).
- `uploadFile(file, opts: {sha256, onProgress(sent,total), signal, chunkSize = 8*1024*1024, api = defaultApi, resumeKey?}) → Promise<string /* upload_id */>`: create (or reuse `sessionStorage["aidoc_upload:<name>:<size>:<lastModified>"]` → `upload_id`, verified via `HEAD`; 404 → create anew), then loop: `PUT ?offset=received` with the slice; `200` → `received = body.received`; `409` → `received = body.received` (continue from there); network error → wait 1 s, `HEAD` → `received`, continue (max 20 consecutive failures → throw); `413`/`422` → throw `ApiError`. On completion remove the sessionStorage key. Decision (index A13): hashing completes **before** the upload is created because `POST /api/uploads` requires the sha256; the worker keeps memory flat.
- `useUploads()` hook: state per file `{file, phase: "hashing"|"uploading"|"done"|"error", progress: 0..1, upload_id?, error?}`, `add(files)`, `cancel(file)`, `retry(file)`.

## Implementation notes / deviations

Recorded while executing P4 on 2026-09-24 (same host as P1–P3), inline on master.

**Task 0 — P3 final-review minors fixed first (failing tests in `tests/api/test_review_fixes_p4.py`)**
- **Duplicate `upload_id` in one `POST /jobs`:** was a 500 (the second input tried to move an already consumed
  file). Now 400 `duplicate_input {upload_id}` before anything is created; the upload stays `complete`.
- **Cancelling a finished job:** was marked `cancelled`. Now a no-op: a `done` (or already `cancelled`) job keeps
  its status and the API answers 200 with the unchanged job. Chosen over 409 so the Web button and
  `aidoc cancel` stay idempotent.
- **Setup while the engine converts:** `POST /system/setup/{engine}` answers 409 `engine_busy {engine, task_id}`
  when the queue's running task uses that engine, when the task has not picked an engine yet (probing; reported
  as `engine: "unknown"`), or for `all` with any running task. Not queued: the user retries when the task ends.
  The reverse direction (a task starting while setup rebuilds its env) is not guarded; `available()` depends on the
  `.ready` marker, which setup rewrites last.
- **`?token=` in the access log:** a `logging.Filter` on `uvicorn.access` (`aidoc.server.logfilter`) rewrites it to
  `token=***`; installed by `aidoc serve` after uvicorn configures logging.
- **Settings comments:** `save_config` now uses `tomlkit` (replaces `tomli-w`): it edits the existing document, so
  comments and layout survive; only changed values are rewritten.

**Independent P3 verifier findings (fixed in P4, failing tests first in `tests/api/test_verifier_p3.py`)**
- **#1 SSRF / NTLM leak through the SPA route (important):** `GET /%5C%5Chost%5Cshare%5Cx` reached `Path.resolve()`
  and Windows opened an SMB connection (21 s hang, then 500). The catch-all now never builds a filesystem path
  from the request: the path must be plain relative POSIX segments (`[A-Za-z0-9._@+-]`, no `\`, `:`, NUL, `..`,
  empty segments or leading `/`), and is only looked up in a table of the files under `web/dist` (rebuilt when
  `index.html` changes). Anything else gets `index.html`. The SPA routes apply the `Host` check when no token is
  set (403 `bad_host`). `/api/docs` and `/api/openapi.json` exist only when no token is set. A `GET` on a known
  `/api` path that only accepts another method is 405 `method_not_allowed` (was 404).
- **#2 PUT to a finished upload:** was a 500 (`status=` collided with the exception's own parameter). Now 409
  `upload_not_receiving {status, received}`. The HTTP status parameter of `ApiError`, `UploadError`,
  `RetryError` and `error_response` is now `http_status`. The Web upload treats `upload_not_receiving` with
  `status: complete` and `received == size` as success (a lost response to the last chunk); any other status
  forgets the saved upload id and fails.
- **#3 non-Latin-1 names:** `download.zip` built `Content-Disposition` raw (UnicodeEncodeError, 500). Now
  RFC 6266/5987: ASCII fallback plus `filename*=UTF-8''…`. `source` already used Starlette's encoder; chunks send
  no filename header.
- **#4 lock liveness:** a live pid whose command line does not look like aidoc is still live when the lock's port
  answers `GET /api/system` with the `workspace` envelope (any status; proxies bypassed, 0.75 s timeout). An
  OS-level lock was not added.
- **#5 SSE starving the thread pool:** streams no longer park a worker thread in `queue.get`. Each subscriber has
  a deque and an `asyncio.Event` set through `loop.call_soon_threadsafe`; idle streams wake once a second to check
  for disconnects. 60 open streams no longer slow a 1 MB upload PUT (test asserts < 1 s).
- **#6 zip followed junctions:** `download.zip` walks without following symlinks or junctions and skips any file
  that resolves outside the output dir.
- **#7 settings:** `server.port` 1–65535; `limits.disk_space_factor` 1–100 000 (large values are how the disk guard is tried out, acceptance row 27); `limits.upload_max_bytes` ≤ 1 TiB;
  other ints ≤ 10⁹; `general.output_dir` may not be a UNC path; changing any `server.*` key is 403
  `server_readonly` (an unchanged value is ignored); a masked (`***`) or unchanged `server.token` is ignored instead
  of 403; a JSON body that is too deeply nested is 422, not 500. The Settings page never sends `server.*`.
- **#8:** NUL in an asset path is 400 `bad_path`; relative `path` inputs are 400 `path_not_absolute`; SSE payloads
  carry `workspace`; a forwarded batch (or `follow_job`) reports each task's current state when the stream opens,
  so the first status line of a task that started earlier is no longer lost.
- **#9:** a `Last-Event-ID` above the newest stored event (DB replaced) gets `resync` instead of silence.
- **Test gaps closed:** the overflow test now proves a resync *frame* is sent (`event_frames`), and
  `test_cancel_during_backoff` waits until the crash is recorded as a transient attempt before cancelling.

**Spec gap closed:** `POST /jobs` accepted only files, but spec §6 page 1 asks for a local *folder* path. A folder
input now expands like `aidoc batch` (recursive, sorted, hidden files and manifests skipped, the output dir
excluded); an empty folder is 400 `no_inputs {path}`.

**Final whole-branch review (fresh reviewer): fixed, each with a failing test first**
- **I1:** `POST /jobs` with several uploads could fail on a later one (`already_converting`) after the job was
  created and earlier uploads consumed, leaving the user stuck. Upload inputs are now checked for a busy task
  before anything is created (`Store.busy_task_id`); the error carries `task_id` and `upload_id`.
  Test: `test_a_busy_upload_leaves_no_half_created_job`.
- **I2:** with an empty `events` table (fresh or replaced DB), a reconnect with a high `Last-Event-ID` replayed
  nothing and then dropped every live event with a lower seq. Any id above the newest stored seq (or above 0 when
  there are none) now gets `resync`. Test: `test_last_event_id_with_an_empty_events_table_resyncs`.
- **I3:** the Library search box was bound to the URL on every keystroke, which broke IME (注音/倉頡) input. It now
  keeps local text, writes the URL 250 ms after typing stops and never during a composition, and follows the URL
  when it changes from outside. Tests: `web/src/pages/__tests__/LibraryPage.test.tsx`.
- **Regraded to Important (the reviewer filed them as Minor):**
  - A 507 `insufficient_disk` answer to an upload chunk was retried as a network error for about 90 s. It now fails
    at once with the disk message.
  - The Settings number fields clamped on every keystroke, so emptying a field showed the minimum and typing "5"
    gave "15". `NumberField` keeps the typed text and clamps on blur.

# P3 — Server + API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Read `docs/superpowers/plans/2026-09-24-index.md` first (§4 schema, §7 config, §8 API contracts are binding). P1 and P2 must be complete.

**Goal:** `aidoc serve` runs a FastAPI server that owns the single job queue, accepts chunked resumable uploads, streams state over SSE, exposes documents/chunks/system/setup/settings endpoints with token auth, and lets the CLI forward batches to it when it is running.

**Architecture:** `server/app.py` builds the app around a `ServerContext` (config, thread-safe `Store`, `EventBus`, `JobQueue`, `UploadManager`). The worker thread calls the P2 `pipeline.run_task` unchanged, passing `emit=bus.publish`. Every state change is written to SQLite first, then published; `/api/events` replays from the `events` table on reconnect. `aidoc.lock` guarantees one queue owner; the CLI reads it to forward work.

**Tech Stack:** FastAPI, uvicorn, httpx (tests + CLI client), psutil, nvidia-ml-py, tomli-w.

**Spec:** §1 (deployment/security), §6 (API, security, SSE), §8.1 (lock, CLI forwarding), §8.4, §8.5 (orphaned), §8.7, §8.8, §9 (setup via Web), §10 (API tests), §12 P3, §13.4.

## Global Constraints

Index §0 plus:
- Every JSON response body includes `"workspace": "default"` (middleware/`envelope()` helper; also on error bodies).
- Never read a local path from a request unless `request.client.host` is loopback or the bearer token is valid.
- No endpoint blocks the event loop on conversion work; conversion runs only in the queue thread.
- Tests use `fastapi.testclient.TestClient` with the fake engine env and a `tmp_root`; the queue thread is not started in tests unless the test says so (`JobQueue.process_next()` runs one task synchronously).

## Review Focus

1. A client sends `PUT /api/uploads/{id}?offset=N` twice for the same chunk (retry after a dropped ACK): the second must return `409` with the current `received`, and the file must not gain duplicate bytes — test in Task 5.
2. `GET /api/documents/{id}/assets/../../aidoc.db` style traversal must be rejected with 400 — test in Task 7.
3. `POST /api/jobs` with a path from a non-loopback client and no token must be refused even when the path is inside the project — test in Task 6.
4. SSE reconnect with a `Last-Event-ID` older than the oldest retained event must produce `resync`, not a silent gap — test in Task 3.
5. Cancelling a job whose task is in the 30 s retry backoff must end the task within ~1 s — test in Task 4 (reuses P2's interruptible wait).

## Implementation notes / deviations

Recorded while executing P3 on 2026-09-24 (same host as P1/P2), commits `f2b4ed4..HEAD` on master. Every
behaviour change below has a test.

**API contract changes are additive only.** They are listed in index §8 under "§8 as implemented in P3", together
with two new index §0 lines: the lock file's content, and the one-queue-owner rule. No row of the §8 table
changed shape.

**Where the plan was adapted (no test was weakened)**
- **T1 (Store):** `Store(threadsafe=...)` is accepted but does nothing. Since P2, every statement already runs
  under one RLock. Schema v2 migrates v1 databases in place (`ALTER TABLE tasks ADD flags_json`).
- **T1 (fixtures):** the shared fixtures (`ctx`, `client`, `token_ctx`, `live_server`) live in `tests/conftest.py`
  from the start, as T10 asked.
- **T1 (loopback client):** the `client` fixture is a loopback client (`client=("127.0.0.1", …)`,
  `base_url=http://127.0.0.1:8765`). Starlette's default test host `testclient` is not a loopback address, so
  local paths were correctly refused.
- **T3/T10 (SSE tests):** Starlette's `TestClient` and httpx's `ASGITransport` both buffer the whole response, so
  an endless SSE stream never returns. The SSE and client tests therefore run against a real uvicorn server in a
  thread (`live_server`). The plan's assertions are unchanged.
- **T3/T10 (SSE behaviour):**
  - `resync` carries no `id:` line.
  - `resync` is also sent when a slow subscriber's 10 000-event buffer overflows.
  - The last event id is accepted as the `Last-Event-ID` header or as `?last_event_id=`.
- **T4 (queue):**
  - **Pause** is checked between segments. The running segment finishes, then the task goes back to `queued`
    with its done segments kept (A16).
  - **Server shutdown** also puts the running task back to `queued`. It is not treated as a user cancel, and the
    task keeps its flags.
  - **Cancelled jobs:** a cancelled job stays cancelled until one of its tasks is retried.
  - **Retry of a done, low or skipped task** resets its segments. Otherwise it would resume the old low-quality
    segments. Failed and cancelled tasks resume instead.
  - **`force`** is cleared only when the run reaches a terminal status.
  - **Tasks run by another process:** the queue skips a queued task whose liveness lock another process holds, so
    it does not spin on it.
- **T4 (SSE payloads):** payloads are API objects:
  - `task.updated` is the Task without `segments`;
  - `segment.updated` is the Segment plus `task_id`;
  - `job.updated` is the Job with its progress.
- **T5 (uploads):**
  - `POST /uploads` also checks free disk space: it needs 3 × the file size, else 507.
  - A PUT that goes past the declared size gets 400 `exceeds_declared_size`.
  - `purge_stale` also removes uploads that completed but were never used, after 24 h, and deletes their rows.
  - The client's filename is reduced to its last path component.
  - A new endpoint, `GET /uploads/{id}`, returns the upload's state.
- **T6 (upload tasks):**
  - An upload task keeps the display name as `source_path`, and that name is never read as a path.
  - The pipeline passes the task's `work_path` to `stage_source(preferred=)`, which only verifies it.
  - Upload tasks are recognised by a non-absolute `source_path`; path tasks always store resolved paths.
  - `POST /jobs` also accepts `origin`, `output_dir` (for the CLI's `-o`, under the same local-path rule) and
    `timeout_s`.
- **T7 (documents):** `GET /documents/{id}` also returns the sidecar. `rescan` also restores orphaned rows whose
  output has come back.
- **T8 (chunks):** a chunk's `source` is the source file's name, as in the spec §5 example and the plan's test.
  This applies to the API and to `aidoc chunk`. When the tokenizer is offline, the API returns 503
  `tokenizer_unavailable` and the CLI prints a one-line error.
- **T9 (settings):** validation also checks JSON types (a bool is not accepted as an int), enums and minimums.
  Known limitation: saving rewrites `aidoc.toml` and drops its comments (tomli-w).
- **T10 (CLI forwarding):**
  - `aidoc convert` is forwarded too (A10), not only `batch`.
  - A forwarded batch writes `_manifest.jsonl` from the DB at the end.
  - Ctrl+C while following a job detaches and exits 0.
- **T11 (`aidoc serve`):**
  - It exits 4 when it cannot listen on the port. uvicorn's own exit code 3 clashed with "another server is
    running" (also 3).
  - After Ctrl+C it exits 0 and prints a "server stopped" line.
  - Maintenance also removes the work dirs of finished or unknown tasks once they are older than the retention
    period. It never touches the work dirs of queued or running tasks.

**Security (coordinator review and final review)**
- **The API token is never written to `data/aidoc.lock`**, because every local process can read that file.
  - The lock now holds `{pid, started_at, host, port, auth}`. This overrides the plan's T2/T11 `LockInfo.token`.
  - `aidoc serve`, `batch`, `convert` and `cancel` take the token from `--token`, then from `AIDOC_TOKEN`, then
    from `aidoc.toml server.token`.
  - A 401 response explains how to pass the token.
- **DNS rebinding and CSRF** (final review I1):
  - With no token set, `/api` answers only requests whose `Host` is a loopback name or the bind address. Anything
    else gets 403 `bad_host`.
  - A non-GET request with an `Origin` header must be same-origin, else 403 `cross_origin`.
  - With a token set, the token is the gate.

**P2 verifier findings fixed in P3 (failing test first)**
- **I1:** the source is always **copied** into the work dir, never hardlinked. Before, an in-place rewrite of the
  original during segment 0 reached segment 1, and the result was cached under the old sha. The spec §8.5 wording
  is updated.
- **I2:** for cross-segment table joins, "touches the edge" is now measured against the page **content**: nothing
  but page furniture (header, footer, page number) lies beyond the table.
  - The old rule used 5 % of the physical page, which ordinary 1-inch margins (about 8.6 %) never met.
  - The column-count rule is kept.
  - The check is `_proto.touches_content_edge`, with a new fixture `span_margin.pdf`.
  - New slow tests for Docling and MinerU fail on the old rule and pass on the new one.
- **Minor 3:** `aidoc chunk` run offline without a cached BPE file gives a clear message pointing at
  `aidoc setup`, and exits 1.
- **Minor 4 (chunking):**
  - Sections that contain only a heading now become heading chunks.
  - An unclosed code fence, `$$` or `<table>` ends at the next heading. Math also ends at a blank line.
  - Text before the first page marker is counted as page 1 only when the page-1 marker is missing; otherwise
    its page is null.
- **Minor 5:** the force-with-open-handle test now proves that a backoff happened, and the cancel test asserts
  that segment 1 is exactly `queued`.

**P2 deferred minors fixed**
- **M2:** done segments are reused only if they were made with the same `lang`, `docling_ocr` and `mineru_tier`.
  `edges.json` records these as `opts_key`; otherwise the segments are redone.
- **M8:** an input failure marks the in-flight segment `failed` instead of leaving it `converting`.
- **M9:** at finalize, `data/work/<task>` keeps only the staged `src.*`. Segment dirs and raw engine output are

- **M12:** Ctrl+C in an in-process `convert` or `batch` now shuts down cleanly. Ctrl+Break behaves the same,
  mapped through SIGBREAK at the console entry point. It kills the runner, cancels the task (which stays

  - M4: PID reuse by another live runner.
  - M5: the runner starts before its PID is recorded.
  - M6: a missing env python or a startup crash falls back slowly.

**Final whole-branch review (fresh reviewer): fixed**
- **I1:** DNS rebinding and CSRF (see Security above).
- **I2:** a retry interrupted by server shutdown ended as `cancelled`, so `force` was cleared and the task resumed
  as a cache hit. The flags are now restored when shutdown requeues the task.
- **I3:** one queue owner. In-process `convert` and `batch` hold `data/cli/<pid>.lock`, and `aidoc serve` refuses
  to start (exit 3) while one is held. `convert` forwards to a running server.
- **I4 (CLI forwarding):**
  - `create_job` has no read timeout, because the server hashes the inputs before it replies.
  - An unreachable server gives a one-line error.
  - `follow_job` stops with "server stopped; job … resumes when `aidoc serve` starts again" once the lock is
    gone, instead of retrying forever.
- **I5:** work-copy retention never deletes the work dir of a task that is queued or running again, such as a
  retried upload.

**Deferred minors (final review)**
- **Server and API:**
  - The static route returns 500 for a drive-letter path.
  - A duplicate `upload_id` in one request gives a 500. An upload error partway through the input loop leaves a
    half-created job.
  - The envelope middleware also rewrites JSON file responses, and 500 responses are `text/plain`.
  - `?token=` appears in the uvicorn access log.
  - Setup from the Web may rebuild an engine venv while that engine is converting.
  - Saving settings drops the comments in `aidoc.toml`.
- **SSE and CLI following:**
  - If `Last-Event-ID` is above the current maximum after a DB wipe, live events are dropped.
  - `follow_job` waits for the next frame after a `resync` that already found the job finished.
- **Queue and jobs:**
  - Cancelling a finished job marks it cancelled.
  - If `stop()` times out, `store.close()` can run while the worker is still writing.
  - The `retry_task` check for a running task is done outside `_state`.
- **Uploads:**
  - Complete uploads are purged by `created_at`, not by completion time.
  - `UploadManager._locks` is never pruned.

# Spike — `mcp` 2.2 SDK against Doc4AI Studio (Task 1)

- Date: 2026-10-02 (Windows 11 host)
- Python 3.12.13 (main env under `uv`), `mcp 2.2.0`, `mcp-types 2.2.0`, `httpx2 2.13.1`, SQLite 3.50.4
- `uv run pytest -m "not slow" -q` after adding the dependency: **482 passed, 53 deselected** (no import breakage).
- Install note: the user's running server holds `.venv/Scripts/aidoc.exe`, so `uv add` could not reinstall the
  editable project. The dependency was added to `pyproject.toml` by hand, then `uv lock` +
  `uv sync --no-install-project --inexact`; test runs use `uv run --no-sync` until the server is restarted.
- Scratch scripts lived in `tests/mcp/_spike/` (deleted): one uvicorn server (FastAPI + `MCPServer` mounted per D2,
  an outer ASGI wrapper that set `scope["state"]["doc4ai"]` and captured headers/bodies, a recording
  middleware) driven by `Client` in both modes, plus raw `httpx2` probes.

### S1 Names
**Finding.** All pre-known names exist with the listed signatures: `mcp.server.MCPServer(name, title, description,
instructions, website_url, icons, version, auth_server_provider, token_verifier, *, …, lifespan, auth, cache_hints,
middleware)`; `MCPServer.streamable_http_app(*, streamable_http_path, json_response, stateless_http, event_store,
retry_interval, max_request_body_size, session_idle_timeout, max_sessions, transport_security, host)`;
`mcp.server.transport_security.TransportSecuritySettings`; `MCPServer.tool(name, title, description, annotations,
icons, meta, structured_output)`; `mcp.types.ToolAnnotations`; `mcp.server.context.ServerRequestContext`;
`mcp.server.mcpserver.exceptions.ToolError`; `mcp.server.caching.CacheHint(ttl_ms, scope)`;
`mcp.client.client.Client`; `mcp.client.streamable_http.streamable_http_client(url, *, http_client=, terminate_on_close=)`.
Differences: the **tool** `Context` (`from mcp.server.mcpserver import Context`) has **no `.connection`**; it has
`.session` (a `ServerSession`: `.client_params`, `.protocol_version`), `.protocol_version`, `.headers`,
`.request_context` (the `ServerRequestContext`, whose `.request` is the Starlette `Request`), `.report_progress`.
`MODERN_PROTOCOL_VERSIONS = ("2026-07-28",)` and `HANDSHAKE_PROTOCOL_VERSIONS` live in `mcp_types.version`.
**Decision.** Use `ctx.session.client_params` / `ctx.request_context.request` instead of `ctx.connection`.
**Affects.** 12, 14, 20.

### S2 Mounting without `Mount`
**Finding.** `app.add_route("/mcp", Wrapper(mcp_app), methods=["GET","POST","DELETE"])` before a catch-all
`/{p:path}` GET route works: `Client(...).list_tools()` succeeds; `GET /anything` reaches the catch-all;
`POST /mcp/` is **not** redirected (405 from the catch-all GET route — never reaches MCP).
**Decision.** D2 stands (no `Mount`, no slash redirect).
**Affects.** 14.

### S3 Both eras in tests
**Finding.** `mode="auto"` → `client.protocol_version == "2026-07-28"` (probes `server/discover`);
`mode="legacy"` → `"2025-11-25"` (`initialize` + `notifications/initialized`, each a separate POST in stateless mode).
Both `list_tools()` and `call_tool()` work. Header passing that works:
```python
http = httpx2.AsyncClient(headers={"Authorization": f"Bearer {token}"}, timeout=httpx2.Timeout(30, read=300))
async with Client(streamable_http_client(url, http_client=http), mode=mode, client_info=info) as c: ...
```
**Decision.** Task 14 copies this into `tests/mcp/conftest.py` as `mcp_client(base_url, token, mode)`.
**Affects.** 14, 23, 24.

### S4 Request object in middleware (both eras)
**Finding.** `type(ctx.request) is starlette.requests.Request` for every message in both eras;
`ctx.request.scope["state"]["doc4ai"] == "marker"` (set by the outer ASGI wrapper) in both; `ctx.request.client`
and `ctx.request.headers["user-agent"]` available. Inside a tool, `ctx.request_context.request` is the same object.
**Extra finding (important).** In the 2026-07-28 era, a `tools/call` that carries arguments makes the SDK run an
**internal `tools/list` through the middleware chain** (same `request_id`, same `Request`) to validate
`Mcp-Param-*` headers (`_streamable_http_modern._tool_input_schema`). It is not an HTTP request.
**Decision.** D1 stands. The middleware records a message only when `ctx.method` equals the HTTP request's
method as seen by the gate (`CallState.method`); a mismatching inner `tools/list` is passed through (still
scope-filtered, which is what the SDK wants: "a visibility-scoped catalog yields exactly what this caller was
advertised") but not logged.
**Affects.** 13, 14.

### S5 Client identity and protocol version
**Finding.** Middleware: `ctx.session.client_params.client_info` (`Implementation(name, version)`) and
`ctx.protocol_version`. Modern era: client info comes from each request's `_meta` envelope
(`io.modelcontextprotocol/clientInfo`); the SDK client sends `("mcp", "0.1.0")` when no `client_info` is given.
Legacy stateless: `client_params` is **None for every message** (each POST is a fresh transport); the
`initialize` message carries it only in `ctx.params["clientInfo"]`, and `ctx.protocol_version` reads the
pre-commit default (`"2025-03-26"`) while handling `initialize` — the real one is `ctx.params["protocolVersion"]`.
Later legacy POSTs carry the `Mcp-Protocol-Version` header (`ctx.protocol_version == "2025-11-25"`).
Tool context: `ctx.session.client_params` (same values), `ctx.protocol_version`.
**Decision.** Client identity = `client_params.client_info` when present; else on `initialize` from
`ctx.params["clientInfo"]` (+ `ctx.params["protocolVersion"]`); else `"unknown"` (D9). To keep legacy clients
from showing up as `unknown` after their handshake, `CallRecorder` remembers the last `initialize` identity per
`(token_id, user_agent)` for 1 hour and uses it for later legacy messages of the same token + User-Agent.
**Affects.** 12, 14.

### S6 Error results with structuredContent
**Finding.** (a) A `structured_output=True` tool that **returns** `CallToolResult(is_error=True, content=[Text],
structured_content={code,message,hint})` reaches the client unchanged (both eras). (b) `raise ToolError(json)` →
`is_error=True`, `structured_content=None`, text `"Error executing tool err_raise: {json}"`. (c) Returning
`CallToolResult(content=[TextContent, ResourceLink], structured_content={...})` from a structured tool works
(both blocks and the structured content arrive).
**Decision.** (a): `registry.doc4ai_tool` returns a `CallToolResult` for failures, and success results may carry
`ResourceLink` blocks next to the text rendering.
**Affects.** 11, 14, 15.

### S7 Client-side output validation on error results
**Finding.** `Client.call_tool` did **not** raise for an `is_error=True` result whose `structured_content`
(`{code,message,hint}`) does not match the output schema, nor for one with `structured_content=None`.
**Decision.** Output models stay success-only.
**Affects.** 11.

### S8 Progress
**Finding.** `await ctx.report_progress(i, 3, msg)` ×3 → the client's `progress_callback` received all three in
**both** modes (`json_response=False`: the response switches to `text/event-stream` once a notification is sent;
plain calls answer `application/json`).
**Decision.** Task 20 uses `report_progress`; its test may assert progress in both eras.
**Affects.** 20.

### S9 `resources/list` pagination and templates
**Finding.** `MCPServer._handle_list_resources(ctx, params)` receives `params` (cursor) but calls
`self.list_resources()` without it. The handler is bound at `__init__` (`on_list_resources=self._handle_list_resources`),
so a subclass override of `_handle_list_resources` does see `params.cursor` — but it is a private method.
`list_resource_templates()` returns templates declared with `@mcp.resource("doc4ai://documents/{doc_id}")`.
A resource function returning `bytes` becomes `BlobResourceContents` (mime from the decorator), `str` becomes
`TextResourceContents` with the declared `mime_type`.
**Decision.** Per A-M9 (the public `list_resources()` has no cursor): list the 100 most recent documents with
`ttlMs = 60000` via `cache_hints`; templates always listed. No private override.
**Affects.** 19.

### S10 `cache_hints` keys
**Finding.** `CacheableMethod = Literal["prompts/list","resources/list","resources/read","resources/templates/list",
"server/discover","tools/list"]`. `cache_hints={"tools/list": CacheHint(300000, "private")}` → the modern client
sees `ListToolsResult.ttl_ms == 300000`; legacy sees `0`.
**Decision.** Keys as planned.
**Affects.** 14, 19.

### S11 `Mcp-Method` header and body shape
**Finding.** Modern POSTs carry `Mcp-Method: tools/call` and `Mcp-Name: <tool>` (also `Mcp-Name: <uri>` for
`resources/read`) plus `Mcp-Protocol-Version: 2026-07-28`; legacy POSTs carry neither `Mcp-Method` nor
`Mcp-Name` (only `Mcp-Protocol-Version` after the handshake). Every body is a single JSON-RPC object with
`"method"`.
**Decision.** D5 stands (header first, body fallback).
**Affects.** 13.

### S12 Rejected Host/Origin, non-JSON POST, GET/DELETE
**Finding.** Bad Host → `421 "Invalid Host header"` (text/plain); bad Origin → `403 "Invalid Origin header"`;
`Content-Type: text/plain` POST → `400 "Invalid Content-Type header"`; malformed JSON → `400` JSON-RPC `-32700`;
`Accept: application/json` only → `406` JSON-RPC `-32600`; `DELETE /mcp` (stateless) → `405` JSON-RPC
`"Session termination not supported"`; `GET /mcp` (stateless) → **200 `text/event-stream` that stays open**
(standalone stream, nothing is ever sent on it in stateless mode).
**Decision.** The gate logs every SDK answer the middleware did not record as `protocol_error` with
`http_status`. The gate answers `GET /mcp` itself with `405` (`Allow: POST`) after authentication: a stateless
server never sends on the standalone stream, so holding the connection open only costs a socket (the spec
allows 405 for GET).
**Affects.** 13.

### S13 401 behaviour of real clients
**Finding.** Claude Code 2.1.286, `claude mcp add --transport http spike401 http://127.0.0.1:38911/mcp --header
"Authorization: Bearer nope"` against a server answering every request `401` +
`WWW-Authenticate: Bearer realm="doc4ai", error="invalid_token"` (no `resource_metadata`): only `POST /mcp`
requests were made (4 of them, UA `claude-code/2.1.286 (sdk-cli)`), **no OAuth discovery**. `claude mcp list`
shows: *"Server rejected the configured Authorization header (HTTP 401). Check that the token is valid for this
MCP endpoint — OAuth fallback is disabled when headers.Authorization is set. Error detail:
{"error":"invalid_token","error_description":"bad"}"* (the JSON body is shown to the user).
**Decision.** Plain error → the Phase 1 header is final; the body's `error_description` is user-visible, so it says
what to do. Cursor / VS Code carried to Task 35.
**Affects.** 13, 35.

### S14 SQLite trigram tokenizer
**Finding.** Main env SQLite 3.50.4: `fts5(..., tokenize='trigram')` works; `MATCH '"學習"'` → no row (2 chars),
`MATCH '"機器學習"'` and `MATCH '"learn"'` → the row; `bm25()` works.
**Decision.** D6 primary (trigram).
**Affects.** 5.
